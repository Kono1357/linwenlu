# 临文录

> 一个纯前端的极简小说创作台。**三个模块，够用就行。**

打开就能写，不用装环境、不用起服务、不用注册。数据留在你自己的浏览器里。

**在线用**：<https://kono1357.github.io/linwenlu/>

## 三个模块

| 模块 | 干什么 |
|---|---|
| **看剧情** | 已写的正文按章排在这里。同一章可以留**多份平行稿**，随时切换比对；选中任意一段就能改写、扩写、提问，或直接存成设定；章节多了可以搜标题和正文。 |
| **提要求** | 用大白话讲要写什么（「主角去码头见旧友，气氛要冷」），AI 流式写出来，**一键落进章节**——续接、存为新版本、或替换当前稿。已经生成的字直接搬运，不重新生成。对话长了能按内容搜、按章筛。 |
| **世界线 / 设定** | 主线、支线、待收的伏笔写进「世界线」；人物、地点、物件、规则写进「设定」。可以搜、可以按类别折叠、可以多选批量删。**它们会自动进入每次生成的上下文。** |

### 人物表：让 AI 自己把配角写出来

设定里标为**「人物」**的条目会**整表**进入每次生成（不受"设定条数"上限约束），并在系统提示里明确要求：出场必须用表里的名字，需要新角色时先表里挑，实在没有再新建。

所以只要把老陈、阿棠们写进设定，你说「主角去码头见旧友」，它就会自己把人对上——**不用每次交代谁是谁**。

### 找得到东西

- 对话长了：**查找** 支持按内容搜，也支持按「未写入 / 某一章」筛
- 设定多了：搜索框 + 按类别折叠 + **多选批量删**
- 导入存档：先给**预览**，四个部分（章节/设定/世界线/对话）各勾各的，可选「合并」或「替换」

### 专注模式

点 ◎ 进全屏阅读，右上角常驻「✕ 退出专注」——不会把你关在里面。

## 怎么用

1. 打开 `index.html`（或者在线版）。
2. 首次进入会让你填模型 —— 任何 **OpenAI 兼容**接口都行，比如：
   - 接口地址 `https://api.deepseek.com/v1`，模型 `deepseek-chat`
   - 或自建/中转的任何兼容端点
   - 以后要改，点右上角 **⚙**（不用翻菜单）
3. 到「提要求」直接说要写什么。生成完点 **写入剧情**。
4. 想让它写得更准，先去「世界线」和「设定」补点料 —— **尤其是标为「人物」的条目**，那是它记住你世界里有哪些人的唯一方式。

> 手机浏览器可以直接「添加到主屏幕」，用起来跟 App 差不多。

## 数据在哪

全部存在**浏览器的 localStorage** 里，不上传任何服务器。

这意味着：换设备、换浏览器、清缓存都会丢。**重要内容请用「⋯ → 数据与导出」定期导出存档**（`.json` 可原样导入回来）。

也能导出正文成 `.md`，或者把写好的 `.txt` / `.md` **按章导入**（识别「第N章 / 第N回 / 第N节」这类行自动切分）。

## 为什么这样设计

它要解决的是一件具体的事：**跟 AI 聊出来的剧情，怎么才能真的落进小说里，而且不写着写着就跑偏。**

两条设计线：

**① 对话即创作通道。** 大多数 AI 写作工具把"聊天"和"正文"分成两个世界，聊天里写的东西要手动复制粘贴，还容易丢。这里生成完直接给「写入剧情」，落盘时带上版本血缘（第几稿、从哪来），不存在"聊了一堆但什么都没留下"。

**② 上下文自动装配。** 每次生成前，系统按预算挑料：作品信息 → 文风约束 → 相关设定（按关键词命中优先，其余按时间补足）→ 未收束的世界线 → 上一章结尾 → 本章已写。可以在「提要求 → 上下文」里**预览这一次到底带了哪些料**。设定条数和带多少字都能调，避免烧不必要的 token。

设定和世界线不是"资料库"，是**喂给模型的事实约束**——这是长文写作不崩的关键。

## 开发

```
index.html            构建产物（Pages 入口，别手改）
src/                  源码（改这里）
├── index.html        骨架
├── style.css         样式（深色纸墨调，移动优先）
└── js/
    ├── store.js      数据层：单一真源 + 本地持久化 + 导入导出
    ├── api.js        上下文装配 + 流式调用 + 失败降级
    ├── read.js       看剧情
    ├── chat.js       提要求
    ├── world.js      世界线与设定
    └── app.js        主控：视图切换 / 抽屉 / 设置
build.js              把 src/ 拼成自包含单文件 index.html
tools/probe.js        浏览器验收探针（CDP 驱动，真机视口 + 截图 + console 抓错）
```

```bash
node build.js                                     # 构建 → index.html
node tools/probe.js index.html probe 390 844      # 验收（手机视口，出 5 张图）
```

`tools/probe.js` 会启动 headless Edge/Chrome，用 CDP 把布局视口真的设成 390×844，跑一遍三个模块、抓 console 报错、量抽屉几何，并输出五张截图。

**为什么需要它**：Windows 上 headless 浏览器的窗口有最小宽度（约 482px），只靠 `--window-size` 根本量不到手机布局；而且它的 `window.innerWidth` 会失真（报 780 而实际布局是 390），所以量视口要认 `document.documentElement.clientWidth`。
